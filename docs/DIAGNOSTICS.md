# Диагностика обрыва Blink iOS

## Включение

Нужны обе обновлённые стороны: новая сборка BlinkCore + iOS-приложения и новая
версия vokop-panel. Старый TestFlight-клиент эти события не отправляет.
`make prepare` пересобирает framework с новыми gomobile API; подмена только Swift
без нового BlinkCore недостаточна. Xcode/устройство в этой Linux-сессии не запускались.

В панели: Vokop → **Диагностика iOS**. Выберите клиента и сессию по времени,
версии и номеру сборки. Идентификатор текущей сессии можно скопировать в Blink:
**Настройки → Журнал событий → Диагностика и журналы**.

При подключении профиля из подписки Blink выводит адрес диагностического API из
HTTPS-ссылки Vokop или стандартной `/sub/` подписки. Это работает, если на том же
origin и base path доступен API панели. Если подписка обслуживается отдельным
доменом/портом, API скрыт другим префиксом или используется отдельный конфиг:

1. В панели выберите клиента и нажмите «Ссылка для отдельного конфига».
2. Вставьте ссылку в поле «Сервер диагностики» в журнале Blink.
3. Повторите подключение и воспроизведите обрыв.

Диагностическая ссылка действует 7 дней и разрешает только создание сессии
отправки событий. Она не даёт доступ к профилям, административному API или
чтению чужих журналов. Явно выбранный сервер диагностики имеет приоритет над
автоматически определённым сервером подписки. Не публикуйте такую ссылку.

## Что записывается

- Этапы приложения: запуск/фон/возврат, начало и отмена подключения, фазы VK и
  CAPTCHA, состояние NetworkExtension, системная ошибка последнего отключения,
  задержка планирования главного потока более секунды без перехода в фон.
- Расширение: старт и чтение профиля, готовность ядра, начало/завершение установки
  маршрутов, состояние транспорта, штатный stop с NEProviderStopReason,
  ошибки запуска и восстановления.
- Heartbeat ещё до установки маршрутов и каждую секунду первых 20 проверок после
  подключения, затем раз в 10 секунд: физическая память процесса, память Go,
  объекты/циклы GC/горутины, счётчики байтов и пакетов, ошибки I/O и задержка
  очереди пакетов. Сами пакеты не записываются.
- Физическая сеть: Wi-Fi/cellular/Ethernet, доступность IPv4/IPv6, индекс
  интерфейса, expensive/constrained, числовой errno отказа привязки сокета.
- Native VK: этап запроса токена, HTTP-статус, числовой error_code VK, разрешение
  TURN, подключение/Allocate, DTLS handshake, smux ready/close и повторы.
  Время native-события сохраняется до выгрузки, связь с сессией не теряется при
  завершении предыдущего подключения.
- Xray: warning/error, классификация по типу внутренней ошибки и счётчик.
  Raw Message.String()/Content не форматируются. Access/DNS traffic logs не
  включаются. WireGuard пишет только ограниченный счётчик ошибок без format/args.

Все сообщения отправляются как фиксированный идентификатор события и числовые
поля из allowlist. URL, пароли, ключи, токены, имена профилей, DNS-имена назначения,
CAPTCHA SID/ответы, cookies и содержимое трафика не входят в wire-формат.
Секреты доставки находятся в общем Keychain; provider preferences содержат
только случайный ID диагностической сессии.

## Доставка и ограничения

Каждое событие сначала сохраняется отдельным атомарным файлом в общем App Group.
App и extension не перезаписывают общий массив. Межпроцессный flock сериализует
обмен credentials и отправку. Удаления из outbox нет до подтверждения конкретного
ID сервером; подтверждённый файл переименовывается в локальный архив. Повтор
после потери ответа безопасен: сервер имеет уникальный session_id/event_id.

Отправка начинается до запуска VPN и продолжается в приложении и расширении.
При сетевой ошибке URLSession дополнительно пробуются TLS-соединения с явным
требованием физических Wi-Fi/cellular/Ethernet интерфейсов. TLS-проверка не
отключается, redirects с Authorization запрещены. Есть ограниченные таймауты и
backoff 5–60 секунд. Доставка не блокирует начало подключения или остановку VPN.
Это попытка физического обхода, а не доказанная на устройстве гарантия bypass:
системные ограничения includeAllNetworks и сеть могут не дать выполнить запрос.

Приложение повторяет доставку при возврате, после отключения и по кнопке журнала.
Если iOS убила процесс до записи, эта запись недоступна. Если убиты оба процесса
или нет связи, немедленная отправка невозможна: сохранённое уйдёт после запуска
при рабочей сети и действующем разрешении. Телеметрия не заменяет jetsam/crash
report iOS и не может гарантировать доставку после удаления приложения.

Хранение ограничено: 7 дней, до 10 локальных сессий; очередь и архив подрезаются
примерно до 500/200 файлов на сессию каждые 100 записей. Native ring — 128 событий.
При переполнении самые старые записи могут быть потеряны. На сервере: 64 события
и 64 КиБ на запрос, 10 000 событий на сессию, 50 000 на клиента, до 30 активных
сессий и 60 новых/час на клиента; очистка просроченного выполняется каждый час.
Ошибки Xray/WireGuard и защиты сокетов ограничены по частоте. Диск, сети и
декодирование истории не выполняются в основном потоке; heartbeat не пишет
на диск синхронно в очереди пакетов.

## Как читать первые 5 секунд

| Наблюдение | Что проверять дальше |
| --- | --- |
| `extension.heartbeat` исчезает, нет `extension.stop`, затем `extension.interrupted` | Нештатное завершение; сравнить footprintBytes и отчёт iOS. Сам marker не доказывает OOM. |
| Растут footprintBytes/goBytes/heapBytes перед обрывом | Риск memory pressure; проверить GC, число потоков и jetsam report. |
| `network.protection_failed` после `extension.routes_ready` | Привязка физического сокета и доступность NIC после смены маршрута. |
| `native.vk.dtls_failed` или `native.vk.retry stage=5` | Отказ handshake между TURN-реле и сервером; сопоставить серверный sidecar. |
| `native.vk.smux_closed`, затем connecting/retry | Потеря транспортной сессии; смотреть последний TURN/DTLS этап. |
| Heartbeat продолжается, TX растёт, RX стоит | Процесс жив; искать потерю трафика, DNS или ошибку outbound, а не считать это crash. |
| `app.main_thread_lag` / высокий queueDelayMs | Задержка планирования UI / обработки пакетов. Это измерение задержки, не stack trace. |
| `sharedStorage=0`, `upload.state errorDomain=9` | App Group / Keychain provisioning. `errorCode` — OSStatus Keychain. |
| `upload.state httpStatus=404/403/429` | API недоступен по этому origin/base path, credential истёк/не подходит или сработала квота. |

Для `native.vk.retry stage`: 0 неизвестно, 1 dial, 2 TURN client/listen,
3 Allocate, 4 DTLS setup, 5 DTLS handshake, 6 KCP, 7 smux, 8 DNS.
Для `native.xray.error stage`: 0 неизвестно, 1 DNS, 2 timeout, 3 неизвестный
корневой сертификат, 4 refused, 5 reset, 6 EOF/closed. severity в errorCode:
1 error, 2 warning. Исходная строка ошибки намеренно отсутствует.
`provider.error errorDomain`: 1 URLSession, 2 NEVPNConnection, 3 BlinkVPN,
4 POSIX, 5 CFNetwork, 6 Blink.VK, 7 NEVPN, 8 Cocoa, 9 Keychain; 0 неизвестный домен.

Apple описывает системные завершения из-за памяти отдельно от crash reports:
[Identifying high-memory use with jetsam event reports](https://developer.apple.com/documentation/xcode/identifying-high-memory-use-with-jetsam-event-reports).
Без такого отчёта или новой сессии конкретная причина обрыва на iPhone не установлена.

## Изменения стабильности

Подготовка geodata теперь потоковая: без полных копий embedded-файла и дисковой
копии одновременно. Регрессионный тест ограничивает allocations проверки до
1 МиБ на вызов. Для extension перед assets/core задан soft Go target 32 МиБ,
GOGC 75; это не жёсткий лимит RSS или гарантия от Jetsam. Для app preflight target
96 МиБ / GOGC 100. [Ограничения Go memory limit](https://go.dev/doc/gc-guide#Memory_limit).

Сокеты используют отдельные мониторы физических интерфейсов вместо монитора
общего маршрута, который меняется при установке VPN. Старт/stop и экспорт
handoff VK вынесены с main actor на последовательную native-очередь.

## Проверка

Go service/controller HTTP, scope/dedup/retention и Vokop regressions — с `-race`.
Native Go tests — включая память, диагностику и TCP/UDP TURN/DTLS/smux обмен
дольше пяти секунд. Проверены frontend typecheck, lint, production build и
компонент просмотра сессии. Cross-repo guard:
`python3 tools/check-diagnostics-contract.py`.

Swift прошёл parser и статические проверки; добавлены XCTest журнала, parser
HTTP и wire fixture. Xcode/Swift type checking/XCTest и работа физического bypass,
фона, memory budget на реальном iPhone в этом окружении не проверены.
